# Repository instructions

Read `CONTRIBUTING.md` before changing this repository. Keep public setup and tests usable without private resources.

For authorized internal integration, app or release work, also read the private development handbook linked from `CONTRIBUTING.md`. If access is missing, report that limitation and continue independent public code/test work; do not invent internal environment details or copy them into this public repository.

Do not commit credentials, customer data, internal operational details or private test artifacts. Separate package/API compatibility changes from documentation/tooling changes. Run checks appropriate to the changed surface, report skips honestly, and review the final exact patch. Do not merge or publish releases without explicit authorization.
